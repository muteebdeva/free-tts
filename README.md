## Why FreeTTS?

Commercial voice AI charges per character and holds your text on someone else's
server. FreeTTS is the opposite:

- 🧠 **A real model, really running locally.** Kokoro-82M (Apache-2.0 weights)
  executes in your browser via ONNX Runtime Web — WebGPU when available,
  WebAssembly fallback. Verified end-to-end in headless Chromium; the release
  gate refuses to pass on mock audio.
- 🔒 **Privacy as a feature, not a policy.** The only network traffic is the
  one-time download of model files from public CDNs. Text is never transmitted
  anywhere. No analytics, no tracking, no secrets in the client.
- 💸 **₹0 forever.** No paid TTS APIs, no GPU servers, no auth service, no
  database. Static hosting + public model CDNs = zero operating cost.
- 📴 **Works offline.** Install as a PWA, download a voice once, generate
  speech with no connection.

## 🚀 Quick start

```bash
npm install

npm run dev        # → http://localhost:3000

npm run build && npm start   # production

npm test                     # 38 unit tests (vitest)

node scripts/verify-audio.mjs   # 🔒 THE GATE: loads Kokoro in headless
                                # Chromium, synthesizes real speech, validates
                                # the WAV bytes. Must pass before any release.
```

On first Generate, the app downloads the speech model (~92 MB quantized for
CPU, ~326 MB full precision for WebGPU) plus the selected voice (~0.5 MB),
then caches them in the browser. Nothing else is ever downloaded.

## 🧬 How it works (30 seconds)

```
your text → sentence chunking (Intl.Segmenter)
          → Kokoro-82M in a Web Worker (never blocks the UI)
          → chunk concat with de-clicking + normalization
          → play in-browser, or export WAV / MP3
```

Models are lazy-loaded: the app fetches weights only for the voice/language
you actually pick, straight from the Hugging Face CDN into Cache Storage.

## 📊 Honest benchmarks

Measured 2026-11-04 on a CPU-only Linux VM (no GPU), headless Chromium,
Kokoro q8 via WASM. Full methodology in [`docs/BENCHMARKS.md`](docs/BENCHMARKS.md).

| Metric | Measured |
|---|---|
| Cold model load (download + init + voice) | 12.3 s |
| Synthesis, dev build (135 chars → 9.17 s audio) | 63.8 s → **RTF 6.96** |
| Synthesis, prod build (68 chars → 4.24 s audio) | 20.2 s → **RTF 4.77** |
| WAV encode (220k samples) | < 100 ms |

**What this means:** on CPU-only devices synthesis runs ~5–7× slower than real
time — and the app *tells you that* instead of faking progress, offering
instant on-device system voices as an alternative. On WebGPU hardware,
third-party measurements report ~4.3× real-time for Kokoro; we haven't
reproduced that here (no GPU on our test machine), so it's cited, not claimed.

## 🗺️ Scope & roadmap

**v1 is honestly scoped:** English only, 28 voices. The underlying model
supports more languages, but the browser pronunciation pipeline currently ships
English phonemization — the UI will never offer a language the engine can't
speak. Long-form output concatenates independently synthesized sentences, so
tiny prosodic seams are possible (we don't claim "seamless"). Browsers may
evict cached models under storage pressure; the app discloses this. No voice
cloning.

**Roadmap:**
1. Multilingual Kokoro — full-language G2P glue to unlock ES/FR/HI/IT/PT voices (per-language pronunciation verification first — no UI claims without it)
2. Piper engine — universal WASM fallback for Safari / no-WebGPU devices
3. Clean-room English G2P — replace eSpeak-NG data to allow permissive relicensing
4. Chatterbox "clone mode" — opt-in zero-shot cloning (WebGPU-only)
